# nxs

Семь скиллов для работы с coding agents: обсудить идею, найти причину сбоя, выполнить задачу, проверить результат и сделать коммит. Каждый скилл устанавливается и вызывается отдельно.

## Установка

```bash
npx skills@latest add -g Villhard/nxs
```

Выбери нужные скиллы и агента в меню. Команда устанавливает опубликованную версию, не локальные правки. Для пробы неопубликованной версии см. [CONTRIBUTING](CONTRIBUTING.md#локальная-разработка-и-публикация).

## Какой скилл выбрать

| Скилл | Когда нужен |
| --- | --- |
| [rnd-grill](skills/rnd-grill/SKILL.md) | Обсудить неясную идею, сравнить варианты и договориться о решении. По запросу сохранить одобренные выводы. |
| [rnd-debug](skills/rnd-debug/SKILL.md) | Воспроизвести сбой и найти причину. Код не исправляет; если данных мало, называет, чего не хватает. |
| [dev-exec](skills/dev-exec/SKILL.md) | Выполнить ясную задачу: согласовать план, внести правки и проверить результат. |
| [dev-review](skills/dev-review/SKILL.md) | Независимо проверить изменения, сохранить замечания и передать выбранные на исправление. Код не меняет. |
| [dev-spec](skills/dev-spec/SKILL.md) | При необходимости записать существенные правила реализованного проекта в `SPEC.md` или частный `.SPEC.md`. |
| [dev-commit](skills/dev-commit/SKILL.md) | Сделать разрешенные атомарные коммиты, не затронув чужие правки. |
| [nxs-setup](skills/nxs-setup/SKILL.md) | Проверить настройки и применить точный одобренный diff. Либо только сообщить готовность. |

Используй синтаксис своего клиента: например `/dev-exec` или `@dev-exec`, если поддерживается. Все скиллы требуют явного выбора; `dev-commit` также принимает прямую просьбу закоммитить, но не обсуждение коммитов. Наличие файлов не доказывает регистрацию или совместимость клиента.

## Примеры

```text
/rnd-grill Как лучше ограничить число запросов к API?
/rnd-debug При повторной оплате создаются два заказа
/dev-exec Добавь поиск по названию товара
/dev-review Проверь все изменения этой задачи
/dev-exec Исправь замечания 1 и 3 из <путь к review.md>
/dev-spec
/dev-commit Только изменения поиска
/nxs-setup project
/nxs-setup project --readiness
```

`dev-exec` сначала показывает конкретный план и ждет одобрения. Выбор замечаний review не разрешает исправление сам по себе: исполнитель подтверждает каждое замечание и согласует план.

Это возможные переходы, не автоматический запуск. Можно сразу выполнить ясный запрос, проверить существующие изменения или закончить без коммита. Уже данное разрешение действует только в своих пределах; `Do not commit` сохраняет силу. Одобренные checkpoint-коммиты возможны и во время исполнения.

- Обсуждение может закончиться без файлов. Сохранение, доменные записи, опыт и реализация имеют отдельные границы согласования. Подготовленный опросник ничего не отправляет; успех прототипа не разрешает перенос, reuse или удаление.
- Малой задаче не нужны spec, ticket, каталог и журнал. `dev-exec` при необходимости готовит [tickets](skills/dev-exec/references/ticket.md) или [контекст продолжения](skills/dev-exec/references/handoff.md). Сохраненная запись не дает новых полномочий и не обещает восстановить сессию другого клиента.
- Review обычно охватывает всю итоговую задачу: нужные checkpoint, staged, unstaged и untracked. `git add` не требуется. Явное сужение сохраняется; неясное владение или пропуск работы останавливает затронутую проверку.
- Установка, миграция и внешнее действие требуют согласия на действие/цель и native permissions. Статус не доказывает результат; после человеческого шага результат проверяется, неизвестный эффект не повторяется вслепую.
- Существующие записи, история и чужие изменения сохраняются. Новые локальные артефакты по умолчанию лежат в `.scratch/<feature-slug>/`, если место не установлено. Feature `spec.md` описывает предложение, project `SPEC.md`/`.SPEC.md` - реализованное и пишется только `dev-spec`.

Подробные схемы в двух темах: [обсуждение](docs/images/grill-light.svg), [диагностика](docs/images/bug-light.svg), [статусы](docs/images/ticket-status-light.svg), [документы](docs/images/artifacts-light.svg), [настройка](docs/images/setup-light.svg). Правила и исключения - в соответствующих скиллах.

## Обновление и настройка

Пример обновления одного скилла: `npx skills@latest update -g dev-exec`. Остальные нужные имена укажи явно. До подтверждения проверь пути, источник и предлагаемые изменения: фильтр имени не фильтрует источник, а меню может предложить удалить другие записи из того же source/ref. Не соглашайся на незапланированное удаление или замену одноименного скилла.

`nxs-setup` не устанавливает каталог и companion bundles. Он отдельно работает с целью, `project` или `global`; отказ и уже актуальная настройка ничего не меняют. `project --readiness`/`global --readiness` только сообщают нужные предпосылки. Обычное обсуждение и исполнение не требуют native reviewers. Правки исходников не обновляют установленные копии и личные настройки.

Чистая установка, обновление, регистрация и полный процесс измененных скиллов пока не проверены. [Карта возможностей](skills/nxs-setup/references/capabilities.md) описывает исходники, не live compatibility; [сценарии](tests/client-scenarios.md) отделяют протокол от наблюдений. Исторические результаты не доказывают новый контракт.
