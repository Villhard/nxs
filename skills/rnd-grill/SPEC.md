# rnd-grill

## Purpose

Resolve the requested idea, question or plan in dialogue. A useful result can be an agreed conclusion or a precise open choice, without a saved decision or development artifacts.

## Ownership

Own the shared discussion and domain-modeling rules. Consumers bundle byte-identical copies so each skill remains independently installable; approved decision and domain-record writes belong to `to-decision`.

## Boundaries

Explicit invocation or an explicit controlled scope authorizes discussion. Taskless discussion creates no journal; discussion within an existing task keeps its required semantic journal records. Discussion itself writes no decision, domain record, feature spec, ticket, product code, Git state, settings or installation.

## Contracts

- Resolve discoverable facts from evidence before asking for priorities. Present independent meaningful choices together, with real alternatives, consequences and recommendations; ordinary discussion waits for the user's choices before deriving dependent questions. A clear request needs no forced interview.
- Keep agreement, proposals, assumptions, feedback and unanswered questions distinct. Resume settled conclusions without reopening them unless new contradictory evidence or the user's request affects them; preserving unfinished state never resolves its open choices.
- Saving requires an expressly authorized saving step under `to-decision` and its content-approval contract. Agreement or HTML approval alone starts no save or subsequent stage. If the saving procedure is unavailable, preserve the discussion and report the missing route rather than substituting another skill.
