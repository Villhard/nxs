# rnd-grill

## Purpose

Investigate uncertainty and agree on a solution through proportionate evidence and meaningful choices. A useful result can remain in dialogue; save approved preparation artifacts directly when requested.

## Ownership

Own discussion, domain modeling, optional evidence and isolated-experiment guidance, and direct approved decision, feature-description, glossary and participant-questionnaire saving. Durable decisions belong to project specs owned by `dev-spec`, not to separate architecture-decision records. Bundle the references and templates needed for independent installation. Project-spec reader rules remain owned by `dev-spec`.

## Boundaries

Explicit invocation or an instruction explicitly covering the work authorizes discussion, not saving or implementation by itself. Preserve existing artifacts, identities and history; their labels are not independent authorization.

Only requested preparation/domain records and explicitly authorized isolated experiment files may be written. Product code/tests, implementation tickets, project specs, Git/index, settings and installations remain unchanged. Production transfer, reuse and deletion of prototype material each need separate authorization. Concrete environment or external actions also require action/target approval and native permissions.

## Contracts

- Resolve discoverable facts from evidence before asking for priorities. Present independent meaningful choices together, with real alternatives, consequences and recommendations; wait for the user's choices before deriving dependent questions. A clear request needs no forced interview.
- Keep agreement, proposals, assumptions, feedback and unanswered questions distinct. Resume settled conclusions without reopening them unless new contradictory evidence or the user's request affects them; preserving unfinished state never resolves its open choices.
- Use dependent-question mapping, primary-source research, opportunity surveys, selected-boundary design and isolated experiments only when the question calls for them. They are optional evidence methods, not hidden mandatory workflows.
- A direct request to save agreed local preparation authorizes the corresponding write without a second content-approval round; agreement alone creates no file. An explicit draft-save request preserves unfinished state and open questions. Use the explicit destination before the established task location or default; create missing/empty targets, preserve source content and manual additions, and make identical repeats a no-op. A conflicting target, unclear scope/owner or concurrent edit requires a concrete conflict and proposed change before writing. Save independently authorized parts without inventing the rest. A decision-save request does not include a glossary unless requested too; feature descriptions are not project specs. Preparing or saving a questionnaire does not authorize sending it.
- Sufficient agreed scope or an approved feature record can feed `dev-exec` directly; a decision/spec/ticket chain is not required. A handoff never starts another skill, implementation or a commit implicitly. Reconcile uncertain effects before continuing after interruption.
