# GLOBAL SETUP

Read the main contract and writing guidance first. Global setup configures shared instructions for the supported clients; it does not install, update, remove or execute skills. Include only configuration needed for the requested scope. Treat private paths, local facts, secrets and client-specific material as private; do not move them into a shared source or repository without explicit approval of the exact content and destination.

## AUDIT

1. Inspect `~/.agents/AGENTS.md` as the shared source and the client instruction files `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` and `~/.config/opencode/AGENTS.md`. Resolve symlinks and group identical real paths. Read existing content and record source, wiring, conflicts and missing paths. Do not assume an unobserved client supports a proposed link.
2. Count `## nxs` headings across the source and any content proposed for merge. Multiple owned sections stop with paths and line numbers for the user to reconcile. For each rule in [global section](../assets/global-section.md), retain an existing equivalent outside the owned section as covered, report contradictions and propose only uncovered rules. Preserve user content and the final newline state outside approved changes.
3. For Claude Code, an import of the shared source or a link resolving to it is wired. For Codex and OpenCode, a symlink resolving to the source is wired. For a missing path propose the import or symlink respectively. Preserve an existing Claude-only layer. For a different Codex or OpenCode file or link, include its complete content in the proposed source merge before proposing replacement of the client path. Group real files so each is merged once; preserve former targets. If privacy or conflicting content prevents a safe merge, report the conflict and stop that change.
4. When the requested scope needs local tracker or domain guidance, inspect [tracker](../assets/issue-tracker.md), [labels](../assets/triage-labels.md) and [domain](../assets/domain.md) and the corresponding existing files under `~/.agents/docs/`. Propose only needed changes; show exact diffs against existing files. Do not replace user text wholesale. Discover real project test and lint commands from that project when requested; do not invent them.
5. Report existing installed skills and provenance only when relevant to the goal. A matching name, directory or lock entry is not authorization to replace anything or proof of native registration. Preserve third-party installations and all user changes. Any separately requested replacement needs exact paths and provenance, preserved modifications, an isolated verified replacement, actual client registration and applicable authorization. If evidence is missing, leave the installation untouched.

## PACKAGE AND APPLY

Show the audit, privacy boundary, exact unified diffs for every file and every proposed link target and replacement in one package. Ask for approval of the complete package; a revision requires showing the revised package. Decline writes nothing. If nothing changes, report already current and stop.

On approval, write exactly the approved source and document changes. Verify merged content before changing any links; stop before linking if verification fails. Apply approved client wiring without modifying former symlink targets. Verify each changed file against the approved package, each link's resolved target and every preserved content and newline sentinel. Report changes, conflicts, missing client capability and unverified registration separately. Never infer workflow compatibility from wiring or readiness.
