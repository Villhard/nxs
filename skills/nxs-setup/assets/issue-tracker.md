# Трекер: локальный Markdown

## Хранилище

Корень проекта: текущий репозиторий. Спецификация задачи - `.scratch/<feature-slug>/spec.md`; tickets - `.scratch/<feature-slug>/issues/<NN>-<slug>.md`. Это локальные файлы, без публикации и синхронизации remote. Для другого корня setup согласует точный путь и изменит эту инструкцию.

## Чтение

Читай файлы по фактическим путям, ticket целиком вместе с `## Комментарии` и записями blockers. Неоднозначный номер уточняй. `to-spec` сохраняет спецификацию задачи, `to-tickets` создает tickets, `dev-exec` исполняет один ticket; project SPEC обновляет отдельно `sync-spec`.

## Запись

Создавай и обновляй Markdown-файлы по согласованному содержанию, сохраняя ручные дополнения и историю. Номера новых tickets - после максимального существующего, без перенумерации. Поля и статусы определяет bundled контракт ticket у `to-tickets`/`dev-exec`. Результаты исполнения и commit IDs добавляй в `## Комментарии`.

## Зависимости и статусы

В `Blocked by` указывай ссылки на реальные tickets либо `None (can start immediately)`, только когда зависимостей нет. До исполнения проверь resolved blockers и их результат в рабочем дереве. Статусы хранятся в `**Status:**`; применяй значения field contract без создания внешних labels.

## Проверка

После записи перечитай файл и проверь содержание, путь, ссылки и статус; при неизвестном результате сначала проверь фактический файл, не создавай дубликат. Setup не изменяет существующие пользовательские records.
