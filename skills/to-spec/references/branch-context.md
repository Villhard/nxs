# Общий контекст веток

Общий record связывает tickets и, если она есть, task spec одного каталога работы. По умолчанию это `<каталог работы>/branch.md`; явное назначение и существующие ссылки определяют выбранный record.

Режим по умолчанию - `feature`: `Spec branch` служит интеграционной веткой tickets, в том числе без task spec, а `Target branch` - конечной целью фичи. В `direct` интеграционной базой служит сам `Target branch`.

```markdown
# Контекст веток

**Mode:** feature
**Target branch:** develop
**Spec branch:** feat/example

## Комментарии

- Согласованный маршрут работы.
```

Для `direct` record содержит `Mode: direct` и `Target branch`, без поля `Spec branch`. Точные имена следуют согласованному контексту и правилам проекта; пример показывает формат.

Tickets и task spec при ее наличии ссылаются на общий record через `**Контекст веток:**` с Markdown-ссылкой относительно содержащего ее файла. В spec ссылка находится в `Решение`, в ticket - рядом с `**Ветка:**`, где хранится его рабочая ветка.

Подготовка сохраняет records выбранного маршрута; Git-ветки и worktrees появляются на этапе исполнения. Комментарии сохраняют значимые решения для продолжения работы.

Review выполняется отдельным вызовом. Пользователь или агент интегрирует результат ticket только по отдельному явному поручению: в `Spec branch` для `feature` или в `Target branch` для `direct`. Интеграция в существующую рабочую ветку другого ticket также требует отдельного явного поручения. Подготовка records и вызов `dev-exec` сами по себе не поручают интеграцию.
