# Проектные спецификации

Project spec описывает реализованное назначение продукта или модуля, его границы, контракты и причины решений. Task spec описывает запланированную работу.

Публикуемые спецификации называются `SPEC.md`, частные локальные - `.SPEC.md` и остаются вне Git. Корневая spec дает общий контекст, модульная - контракты своего каталога. Назначение документа определяется содержанием вместе с именем.

Для работы полезны применимые корневые и модульные specs, затем связанные контракты затронутых компонентов. Их термины и решения связывают код с намерением; противоречия становятся вопросами обсуждения. Отсутствие specs допустимо.

`sync-spec` обновляет существенные контракты после реализации. Остальные skills используют specs как контекст своей задачи.
