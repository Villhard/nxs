# ЗАДАЧА

Читай до записи/исполнения ticket. Правила и [шаблон](../assets/ticket.md) принадлежат `dev-exec`. Tickets необязательны; малому ясному запросу файл не нужен.

## ШАБЛОН

Прочитай шаблон и сохрани форму: заголовок, `**What to build:**`, `**Blocked by:**`, необязательный `**Branch:**`, `**Status:**`, приемка строками `- [ ]`, затем `## Условия завершения`. Источники, IDs выбранных замечаний и нужные проверки помести в поведение/критерии, не создавай второй протокол метаданных.

Копируй `## Условия завершения` дословно из шаблона независимо от языка остального ticket. Блок задает исполнителя, предпосылки и условие завершения, не дублирует полные инструкции. Существующие tickets сохраняют текст исполнения, заголовки (в том числе `## Done when`, `## Comments`) и `Do not commit` до отдельно согласованной правки; новый шаблон их не мигрирует. Новые заметки пиши в "Комментарии", в старом ticket используй его существующий раздел.

## НУМЕРАЦИЯ

По умолчанию `.scratch/<feature-slug>/issues/NN-<slug>.md`, но явное установленное место важнее. До номера прочитай все issues, включая решения и отклоненное. Если `issues/` пуст/отсутствует, `NN` = `01`, иначе следующий после максимального. Новые номера идут по зависимостям: новый блокер раньше зависимого. Не перенумеровывай и не пересоздавай существующие.

## ПОЛЯ

- `**Blocked by:**`: сначала номера (`01` или `01, 03`), после каждого можно название. `None (can start immediately)` только при отсутствии зависимостей; неизвестность не равна `None`. `resolved` разрешает старт, но не доказывает результат: "Условия завершения" требуют проверки результата блокера в рабочем дереве до правок.
- `**Branch:**`: явно одобренная ветка либо предложение `<type>/<feature-slug>` по правилу проекта; type из работы (`feat`, `fix`, `refactor`, `chore`, `docs`). Даже без правила проекта предложи ветку. Покажи до сохранения; пользователь может изменить/убрать. Без поля выполняй на текущей. Сохрани старые ограничения, не переписывай историю ради их согласования.
- `**Status:**`: изначально `ready-for-agent`; `needs-info` допустим лишь для явно разрешенного черновика с изолированным открытым `[NEEDS CLARIFICATION: ...]` в его теле. Существенный вопрос в `spec.md`/`root-cause.md` блокирует создание новых tickets до ответа. `ready-for-human`/`resolved` - состояния исполнения, не начальные. После человеческого шага человек возвращает `ready-for-agent` и возобновляет исполнителя; тот проверяет результат. `wontfix` требует решения пользователя или явного исключения существующего ticket; невоспроизведение само не отклоняет новую работу.
- Checkboxes - наблюдаемые критерии, отмечаемые после проверки. Шаги реализации храни в одобренном плане, не `### Task`. Старые review-origin исключения невоспроизведения действуют лишь в разрешающих их tickets; иначе сохрани замечание/пробелы, не убирай критерии и не заявляй исправление.
- Нет `## Parent` и обратной ссылки: связь со spec/root cause - общий каталог функции.
