# HANDOFF

Read before saving resumable context on request or an agreed stop. `dev-exec` owns this guidance and the [handoff template](../assets/handoff.md). A normal result in dialogue needs no saved handoff, task directory or journal.

## RECONCILE AND SAVE

1. Resolve the task from explicit input or unambiguous current context, not a branch name alone. Missing explicit paths stop; ask if multiple tasks fit. Read relevant task records, prior handoffs and any existing history needed for continuation. Reconcile recorded claims with actual artifacts, Git and observable effects; a prior completion claim is not independent verification.
2. Separate accepted decisions/outcomes, open questions and unverified claims/effects. Preserve approved scope, constraints, requirements, dependency evidence, source identities/paths and relevant pins. Keep exact unanswered question identifiers and wording where present. Name observations needed before any retry of an uncertain commit, migration or external action; never replay it automatically.
3. Reuse an explicit or established destination. For a known feature, default to `.scratch/<feature-slug>/handoff.md`; otherwise use a user-selected destination or `.scratch/handoffs/<task-slug>.md` for an unambiguous task. Ask if ambiguous. Preserve existing handoff history and unrelated content. Link a relevant existing journal as context if useful, but create no journal or event protocol.
4. Use the template with enough standalone context for the intended consumer. Include the repository, actual branch and Git state, intended-work baseline, acceptance/check status and remaining staged, unstaged and untracked task changes. Identify foreign changes separately. For checkpoints, include pre-checkpoint HEAD, each verified commit and parent OID, approved scope and changed paths. Unknown identities or omitted intended work remain explicit blockers; ancestry alone proves no net coverage.
5. Carry exact verification commands/results and NOT RUN limitations. Respect explicit limits on state inspection or checks and label unobserved state rather than inventing evidence. Exclude secrets and unnecessary private transcripts. A native session identity is client-specific and promises no cross-client recovery.
6. Re-read the saved content and relevant links within the authorized scope, then report the path, blockers, unverified effects and next authorized action. The next consumer rechecks its own intended-work coverage, choosing an agreed earlier baseline for checkpoints already on the normal base. Saving never grants implementation, commit, external-action or replay authorization and never starts the next skill automatically.
