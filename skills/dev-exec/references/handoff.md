# ПЕРЕДАЧА КОНТЕКСТА

Читай до сохранения контекста по запросу/согласованной остановке. Правила и [шаблон](../assets/handoff.md) принадлежат `dev-exec`. Обычному ответу не нужны handoff, каталог и журнал. В старых handoffs английские заголовки читай как соответствующие русским; только ради перевода файл не переписывай.

## СВЕРКА И СОХРАНЕНИЕ

1. Установи задачу по явному входу/однозначному контексту, не ветке. Отсутствующий явный путь останавливает; несколько задач требуют выбора. Прочитай нужные записи, прежние handoffs и историю. Сверь заявления с артефактами, Git и эффектами; прежнее "готово" - не независимая проверка.
2. Раздели принятые решения/результаты, вопросы и непроверенные заявления/эффекты. Сохрани охват, ограничения, требования, зависимости с доказательствами, источники/пути/pins. Идентификаторы и текст открытых вопросов сохраняй точно. Назови наблюдения до повторения сомнительного коммита/миграции/внешнего действия; не повторяй автоматически.
3. Используй явное/установленное место. Для известной функции - `.scratch/<feature-slug>/handoff.md`, иначе выбор пользователя или `.scratch/handoffs/<task-slug>.md` для однозначной задачи. Неясность уточни. Сохрани историю и постороннее. Полезный существующий журнал можно сослать как контекст, но не создавай журнал/event protocol.
4. По шаблону дай самостоятельный контекст адресату: репозиторий, реальную ветку/Git, baseline задачи, приемку/проверки и оставшиеся staged, unstaged, untracked изменения; чужие отдельно. Для checkpoint - pre-checkpoint HEAD, каждый проверенный commit и parent OID, охват и пути. Неизвестные идентичности/пропущенная работа - явные блокеры; ancestry не доказывает итоговое покрытие.
5. Сохрани точные команды/результаты и ограничения NOT RUN. Соблюдай запреты осмотра/проверок, непроверенное пометь, не выдумывай. Исключи секреты и ненужные частные диалоги. Native session ID зависит от клиента и не обещает восстановление между клиентами.
6. Перечитай сохраненное и ссылки в разрешенных пределах. Верни путь, блокеры, непроверенные эффекты и следующий разрешенный шаг. Следующий исполнитель сам проверяет покрытие; для checkpoint на обычной базе нужна согласованная более ранняя baseline. Сохранение не разрешает реализацию, коммит, внешнее действие/повтор и не запускает следующий скилл.
