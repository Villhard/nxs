# ОБЩИЙ КОНТЕКСТ ВЕТОК

Владелец - `to-tickets`; `to-spec` и `dev-exec` получают одинаковые bundled copies. Это контракт локальных records, не разрешение на изменение Git или исполнение.

## ВЫБОР И СОГЛАСОВАНИЕ

Каталог работы содержит необязательную task spec и `issues/`. По умолчанию общий record - `<каталог работы>/branch.md`. Явное локальное назначение и существующая ссылка `**Branch context:**` важнее default: разрешай относительную Markdown-ссылку от содержащего ее record, не от cwd. Для нестандартного `issues/` каталог работы - его родитель, если пользователь не указал иной. Не ищи контекст в соседних каталогах. До записи прочитай явно выбранный источник, spec, связанные tickets и общий record целиком с комментариями. Отсутствующий явно указанный источник или контекст по существующей ссылке останавливает запись; не создавай замену по default.

При отсутствии контекста покажи маршрут и согласуй точные имена. Default режима - `feature`: отдельная общая spec-ветка служит интеграционной базой tickets, конечная целевая ветка - целью будущего PR/MR всей фичи с task spec. Режим `direct` допустим только по явному выбору: интеграционная база совпадает с конечной целью, spec-ветки нет; общая task spec не обещает единый PR/MR фичи. Не считай цель автоматически `main`, не выводи согласие из текущего HEAD, имени каталога или наличия ветки. Имена предлагай по применимым пользовательским/проектным соглашениям. В `feature` spec-ветка и цель различны.

Известный неизменный выбор используй без нового вопроса, в том числе в новой сессии. Изменение режима, имен, базы или противоречащие указания требуют отдельного решения до затронутой записи. Наличие records не разрешает автоматически переименовывать ветки, мигрировать старые tickets или присваивать существующую Git-ветку.

## RECORD И ССЫЛКИ

Новый общий record имеет форму:

```markdown
# Контекст веток

**Mode:** feature
**Target branch:** develop
**Spec branch:** feat/example

## Комментарии

- Согласованы режим и точные имена; Git не изменялся.
```

Для `direct` сохраняй `**Mode:** direct` и точную `**Target branch:**`, строку `Spec branch` не добавляй. Интеграционная ветка вычисляется из режима и этих полей, не хранится вторым настраиваемым полем. Согласие и значимые решения сохраняй в комментариях; не выдавай пример имен за default. Неизвестный режим, повторяющиеся противоречивые поля, spec-ветка в `direct` или несовместимые ссылки/решения останавливают затронутую запись до разрешения конфликта.

Task spec и каждый новый согласованный ticket содержат `**Branch context:**` с явной Markdown-ссылкой на один этот record. В spec размещай ссылку внутри `Решение`, в ticket - рядом с `Branch`. Не копируй общие настройки в spec/tickets: единственный источник - общий record. Точная рабочая ticket-ветка хранится в `**Branch:**` самого ticket. Для разрешенного незавершенного черновика несогласованные ветки не выдавай за согласованные.

## ЗАПИСЬ И ОСТАНОВКИ

Подготовка разрешает только согласованные локальные records: выбранную spec либо tickets и общий контекст. Она не создает/переключает ветки или worktrees, не меняет refs, HEAD, index, исходные файлы продукта, установки или settings; не делает fetch, commits и не запускает другие skills. Git допустим только для чтения контекста.

До необходимого согласия не создавай records и каталоги. Непосредственно перед записью сверяй прочитанные источники и цели, включая общий record. Сохраняй ручные дополнения, историю и незатронутое содержимое; неизменный повтор - no-op без дубликатов. При несовместимой конкурентной правке, неясном владении или конфликте с общим контекстом останови затронутую запись, покажи конфликт и дождись решения, не выбирай удобную версию. После частичной либо неизвестной записи перечитай фактические файлы, восстанавливай только согласованное без дублирования. Не перезаписывай чужое и не откатывай автоматически уже сохраненное. Records соседних каталогов, старые записи и установки не мигрируются автоматически.
