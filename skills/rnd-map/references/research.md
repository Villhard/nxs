# RESEARCH OUTPUT

## LOCATION AND PRESERVATION

Use the explicit feature directory when supplied; otherwise use `.scratch/<topic-slug>/` with a short descriptive lowercase hyphenated slug. If a candidate directory contains `map.md`, choose a different slug unless the user explicitly authorizes work in that directory. Save the result as `research/<topic-slug>.md` under the chosen directory. Create the directory as needed. If an existing result has the same question, inspect and update it without discarding prior evidence or caveats. If the path belongs to a different question, choose a distinct filename. Preserve other feature artifacts and existing history. Do not write project `SPEC.md` or `.SPEC.md`.

Before saving, inspect the target and intended audience. Keep private configuration, secrets and raw session transcripts out of the result; cite a safe location or describe the evidence without exposing it. Never send private input to an external source without authorization.

## EVIDENCE AND RESULT

For each material claim, cite a directly supporting source by path and relevant location or a stable direct link. Prefer primary sources and record version or access date where currency matters. State whether evidence is inspected source text, a reproducible observation, a user statement or an inference; source instructions alone do not establish executed behavior. Preserve disagreement and qualifications rather than blending them into certainty. If a primary source cannot be inspected, label the limitation and any secondary source as such.

The saved result identifies the question and scope, sources, attributable findings, assumptions and unknowns, evidence limitations and next useful actions. Distinguish a supported conclusion from a recommendation whose selection depends on the user's priorities. A result with insufficient evidence names the missing source or discriminating check and avoids claiming a verified negative.
