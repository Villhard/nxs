# ФОРМАТ КОММИТА

Читай до коммита. `dev-commit` следует этим правилам и определяет его содержимое.

## СООБЩЕНИЕ

```text
<type>(<scope>): <subject>
```

Одна строка, без тела и trailers (`Co-Authored-By`, `Signed-off-by`), если пользователь явно не попросил. Шаблон клиента это не отменяет. Subject максимально короткий, полностью lowercase, включая сокращения (`seo`, не `SEO`). Типы: `feat` - функция, `fix` - ошибка, `refactor` - без смены поведения, `chore` - зависимости/настройки, `docs` - документация.

Scope - затронутая область: модуль, plugin, в заметках тема/скилл. Предпочитай уже используемый в `git log --oneline -20`.

Используй простые глаголы действия: add, fix, remove, update, show, hide, validate.

## ПРАВИЛА GIT

- Stage явные пути/hunks; никогда `git add -A`, `git add .`, `git add -f`.
- Перед коммитом просмотри точный staged diff.
- Никогда `--force`; `--no-verify` - только по явному согласию.
- Не amend опубликованный коммит.
- После ошибки hook осмотри состояние, не считай коммит созданным. Если нужен кодовый fix, остановись и сообщи; после исправления повтори обычным коммитом, не amend прежний.
