# SELECTED REVIEW FINDINGS INPUT

Read [review report](review-report.md) and its VALIDATION and CURRENCY rules. Require a complete current report and a separate selection record naming its exact path, an exact saved report snapshot and snapshot SHA256, selected finding IDs, approved grouping and rationale, choices and approval source. Verify the snapshot hash and compare the current report byte-for-byte with the snapshot, allowing only ticket-link changes for selected findings to tickets already created or covering them; recheck those links against existing issues. Recompute every scope and requirement pin before any write. A changed, malformed, incomplete or stale report, unknown or ambiguous selection, missing grouping or material decision stops the affected work. An empty selection creates nothing. Outside-scope findings remain follow-ups.

Read all existing issues at the feature or review destination. An open ticket already covering a selected finding is linked unchanged; never modify its status, criteria or comments. Recheck coverage and all source bytes immediately before saving, so repeating the same selection creates no duplicate. Preserve resolved and wontfix history. Respect the selection and grouping exactly; unselected findings create no tickets. If an unresolved choice is explicitly selected, isolate it as `needs-info` with a clarification marker; do not guess.

For each authorized group, create a ticket in the report's feature `issues/`, or `.scratch/reviews/<branch-slug>/issues/` when no feature resolves. Apply the bundled ticket rules and template, exact current branch and normal dependency checks. Include exact source finding IDs and locations, the grouping rationale and corrected behavior. Preserve plausible verdicts and their confirmation evidence. The first criterion is exactly:

`- [ ] Each finding reproduced before the change, with evidence under ## Comments; a finding that did not reproduce is named there and its criteria removed; if none reproduced, set **Status** to wontfix and stop.`

Add one observable fix criterion per finding and a regression check when the project has a test suite. After saving, update only selected findings' `ticket: proposed` entries to their ticket paths, including existing coverage; preserve every other report byte. Revalidate currency and the allowed report difference before each update. Return created and reused paths and suggest the `/dev-exec` handoff only for eligible ready tickets. Never execute or change the index.
