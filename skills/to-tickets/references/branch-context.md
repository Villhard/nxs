# Общий контекст веток

Общий record связывает task spec и tickets одного каталога работы. По умолчанию это `<каталог работы>/branch.md`; явное назначение и существующие ссылки определяют выбранный record.

Режим по умолчанию - `feature`: общая spec-ветка служит интеграционной базой tickets, Target branch - конечной целью фичи. В `direct` интеграционной базой служит сама Target branch.

```markdown
# Контекст веток

**Mode:** feature
**Target branch:** develop
**Spec branch:** feat/example

## Комментарии

- Согласованный маршрут работы.
```

Для `direct` record содержит `Mode: direct` и `Target branch`, без поля `Spec branch`. Точные имена следуют согласованному контексту и правилам проекта; пример показывает формат.

Task spec и tickets ссылаются на общий record через `**Контекст веток:**` с Markdown-ссылкой относительно содержащего ее файла. В spec ссылка находится в `Решение`, в ticket - рядом с `**Ветка:**`, где хранится его рабочая ветка.

Подготовка сохраняет records выбранного маршрута; Git-ветки и worktrees появляются на этапе исполнения. Комментарии сохраняют значимые решения для продолжения работы.
