# Параллельная реализация сводится в feature branch

Независимые изменения могут идти параллельно в отдельных Git worktrees. Lead объединяет их в одной feature branch. Это исключает одновременные правки одного checkout, но не доказывает корректность совмещенного поведения.

Этап идет после проверки [последовательного цикла и восстановления](0005-bounded-runs-and-recovery-first.md).

Lead может сам вызвать `dev-commit` для проверенного результата и merge ветки в feature branch, сохраняя историю. Ticket executor по-прежнему заканчивает без коммита; коммиты организует lead отдельной стадией. Для реализации нужен merge-completion контракт `dev-commit`.

Ветка ticket соответствует worktree, результаты блокеров реально есть в нем. Зависимое запускается от интегрированного feature state после совместной проверки предпосылок. Изолированные тесты не заменяют integrated checks.

Ignored task records/private `.SPEC.md` не появляются в новом worktree сами. Контекст и private specs требуют явной передачи/доступа. Этот механизм, concurrent journal и integration conflicts пока открыты.
