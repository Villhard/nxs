# Участие в разработке

`CLAUDE.md` и `AGENTS.md` - равнозначные точки входа.

## Структура

Каждый из [девяти skills](README.md#какой-скилл-выбрать) устанавливается отдельно: `SKILL.md` содержит metadata и этапы, `agents/openai.yaml` - policy Codex, `references/` - контракты, `assets/` - шаблоны. Ресурсы внутри каталога обеспечивают автономную установку.

| Владелец | Reference и потребители одинаковых копий |
| --- | --- |
| `sync-spec` | `project-specs.md`: `rnd-grill`, `rnd-debug`, `to-spec`, `to-tickets`, `dev-exec`, `dev-review` |
| `to-tickets` | `ticket.md`: `dev-exec`; `branch-context.md`: `to-spec`, `dev-exec` |
| `dev-commit` | `commit-format.md`: `dev-exec` |

Владелец и bundled copies обновляются вместе. Шаблоны принадлежат соответствующим writers: `to-spec`, `to-tickets`, `sync-spec`.

## Стиль

Короткий русский текст, обычный регистр заголовков, ASCII-дефис и прямые кавычки. Цель, этапы и связи важнее подробного алгоритма. Форматы records, metadata и пути обеспечивают взаимодействие artifacts.

README описывает использование, SPEC - реализованные контракты, skills и references - работу. Примеры нейтральные; частные данные остаются вне публикации.

<a id="checks"></a>

## Проверки

Frontmatter, configs, локальные ссылки и одинаковые copies проверяются вместе с измененными handoffs. Disposable fixture показывает создание records, повтор и фактическое поведение измененного flow. Минимальный достаточный набор проверок охватывает измененное поведение, требования и AC, применимую регрессию и обязательные стандарты; связанные AC можно проверять вместе, если это не скрывает ошибки. Повтор или расширение снимает конкретную неопределенность, а не становится полным аудитом по умолчанию. Review охватывает стандарты и требования.

Наблюдаемые результаты и непроверенные границы совместимости различаются в отчете. Установочные файлы сами по себе не доказывают live invocation клиента.

<a id="local-development-and-release"></a>

## Локальная разработка и публикация

Candidate smoke получает текст `SKILL.md` и абсолютный путь его ресурсов из checkout. Одноразовые repos отделяют проверку от пользовательских данных и установок. Для поведенческого smoke обычные входы и требования не подсказывают действия, которые обязан обеспечить skill; ожидания и assertions отделены от задания исполнителю. Guided-прогон служит диагностике и не заменяет нейтральное доказательство.

Публикация и обновление установок - отдельные операции; изменения source не обновляют установленную версию.
